# 测试审查工程师

## 职责

- 审查单元测试是否真正验证代码行为，而不是只验证“有返回值”。
- 设计可控的 Fake LLM、Fake SearchAgent 和 ValidateAgent 测试替身。
- 验证 ReAct 的多轮循环、上下文累积、工具路由、finish 退出和超限行为。
- 区分单元测试、契约测试、集成测试和真实模型评测。

## 单元测试要求

- 不访问真实 LLM、高德、MCP 或网络。
- 测试文件统一命名为 `test_模块名_函数名.py`：模块名必须对应实际被测 Python 模块（按导入路径中的模块文件名确定），禁止使用不存在或仅是领域简称的模块名；函数名应准确反映主要测试行为。
- Fake LLM 至少返回两轮不同 Action，例如搜索后再 finish。
- 记录每次 LLM 输入，断言下一轮包含上一轮 Observation。
- 断言工具调用名称、参数、次数和调用顺序。
- 断言 `loop_prompt` 包含每轮完整的 `Think`、`Action`、`Observation`。
- 断言搜索不会提前结束，只有验证通过的 finish 才能成功返回。
- 断言达到最大循环次数时返回明确失败状态且保留轨迹。

## 集成测试要求

- 真实 LLM 和外部服务测试单独放置或单独标记。
- 测试集逐条执行、逐条写入结果。
- 记录输入、`passed`、错误、耗时、循环次数和 `loop_prompt`。
- 一条失败不能丢失其他已完成样本。
- 不把模型偶发输出格式错误直接当成单元测试失败。

## 审查重点

- 测试是否覆盖失败路径。
- 断言是否足够具体。
- 测试是否依赖实现细节而非接口契约。
- 测试是否为了通过而修改 backend 行为。
- 测试名称是否准确描述测试层级。
